# VisualXtsi

A C++ and Unreal Engine productivity extension for Visual Studio 2022 and later, built for large,
multi-platform (including console) codebases, with first-class support for Unreal Engine C++
(UE 4.27 and all UE5 versions).

## Architecture

- **engine/**: a native C++ DLL that holds all of the real logic (parsing, classification,
  and later indexing and navigation). It exposes a flat C ABI (`vx.h`). It doesn't use C++/CLI.
- **vsix/**: a thin C# VSIX shell. It exists only because Visual Studio's editor extension
  points (MEF classifiers, QuickInfo, etc.) are managed-only. It forwards work to the engine
  through P/Invoke.

Text offsets crossing the ABI are in UTF-16 code units, matching the VS editor buffer.

## Building

Requirements: Visual Studio 2022 with the "Desktop development with C++" and
"Visual Studio extension development" workloads, CMake 3.20+, and an LLVM 19 install
(for libclang; the official `clang+llvm-19.1.5-x86_64-pc-windows-msvc` archive or the
`LLVM-19.1.5-win64.exe` installer). Point `VX_LLVM_ROOT` at it (CMake cache variable or
environment variable; default `C:/Program Files/LLVM`). Without it the engine still builds,
with lexical classification only.

```
cmake -S engine -B build/engine -G "Visual Studio 17 2022" -A x64 -DVX_LLVM_ROOT=<llvm root>
cmake --build build/engine --config Release
ctest --test-dir build/engine -C Release
msbuild vsix/VisualXtsi.Vsix/VisualXtsi.Vsix.csproj -restore -p:Configuration=Release -p:VxLlvmRoot=<llvm root>
```

## Compile arguments

The engine finds arguments for a file by itself (`vx_discover_args`): first a
`compile_commands.json` in a parent folder that lists the file, then the Unreal Build Tool
project files of the enclosing project (`Intermediate/ProjectFiles/*.vcxproj`, generated by
"Generate Visual Studio project files"; UE 4.27 and UE5 layouts). Headers use the arguments
of the nearest source file of their module. Files are parsed in the background when opened
and reparsed shortly after edits; progress is logged to
`%LOCALAPPDATA%\VisualXtsi\VisualXtsi.log`. Function bodies in included headers are skipped
(the open file keeps its own), which makes first parses about a third faster and reparses
about four times faster on Unreal code; set `VX_FULL_PREAMBLE=1` to compare against full parsing.

After the first file of an Unreal module is parsed, a shared precompiled header for the module
is built in the background: the engine and plugin headers that at least a fifth of the module's
source files reach (directly or through the project's own headers), leaving out any that do not
compile on their own. Later files of the module start from it (on Lyra, about 1.5 s instead of
about 4 s). PCHs live in `%LOCALAPPDATA%\VisualXtsi\pch`, are rebuilt when the module's
arguments or any header in them changes, and the least recently used ones are evicted beyond
`VX_PCH_CACHE_MB` (default 4096).

## Coloring

Two classifiers feed the editor. A lexical one (instant, no parsing) colors preprocessor
directives and macro-like names. A semantic one colors identifiers by what they name (locals,
parameters, member fields, globals and statics, types, enum constants, namespaces, functions,
methods, static and virtual methods), using the last background parse; edits only recolor the
spans whose classification changed. Every category has its own entry under Tools > Options >
Environment > Fonts and Colors (names start with "VisualXtsi"); defaults suit the dark theme.

## Navigation

| Command (Keyboard options name) | Default key | What it does |
| --- | --- | --- |
| `VisualXtsi.ToggleHeaderSource` | Alt+O | Header ↔ source: same folder, Unreal Public/Classes ↔ Private, the module, include paths |
| `VisualXtsi.OpenFileInSolution` | Shift+Alt+O (editor) | Fuzzy file search over the solution folder and Unreal project(s); `name:123` opens at a line |
| `VisualXtsi.FindSymbolInSolution` | Shift+Alt+S | Fuzzy search over a persisted index of the project's declarations; `Scope::name` narrows |
| `VisualXtsi.GoToDefinition` | Alt+G (editor) | Definition of the symbol at the caret (libclang, then the symbol index); on a definition, its declaration |

Visual Studio binds Shift+Alt+O and Alt+G globally (File.OpenWebSite, Edit.BriefBrowse), so ours
apply in the text editor only. All four are under the Edit menu and can be rebound. The engine
source can be indexed too (Options > VisualXtsi > Navigation; off by default, ~0.8 GB).

## Options

Tools > Options > VisualXtsi > General holds what Fonts and Colors cannot: switching each
coloring category and the macro tooltip on or off, skipping function bodies in included headers,
the shared PCH and its cache size limit, and a button that clears the PCH cache. Settings are
stored in the Visual Studio user settings store (collection "VisualXtsi") and are also
available to automation as `DTE.Properties("VisualXtsi", "General")`. The environment variables
`VX_FULL_PREAMBLE`, `VX_PCH_CACHE_MB` and `VX_PCH_DIR` override the parsing settings.

## Packaging

A release package is one command; it builds the engine, runs its tests, builds the VSIX and
checks its contents, writing `dist\VisualXtsi-<version>.vsix` (version from the manifest):

```
powershell -ExecutionPolicy Bypass -File scripts\package.ps1 -LlvmRoot <llvm root>
```

The build copies `libclang.dll` and clang's builtin headers (`clang-resource/include`)
next to `vxengine.dll`, and the VSIX packages them. `vxcli` (built with the engine) parses a
file and prints macro information: `vxcli <file> [@args.rsp] [line:col ...]`.
